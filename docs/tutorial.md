# 五步法 — 从 0 搭一个打比赛的 Agent（完整教程）

> 这是小红书教程的完整版。配套代码在本仓库（六模块，其中融合器与编排循环
> 为设计占位——完整实现属系统层，见 README 分层声明）。
> 推荐配合 [PROMPT.md](../PROMPT.md) 使用：让 AI 按五步带你逐模块搭。

## 先想清楚：agent 是谁

不用一上来就搞全自动。这个框架里的 agent 是六个零件，每个零件都是把
"我自己怎么干活"翻译成代码：

| 我怎么干活 | 翻译成 |
| --- | --- |
| 我踩过的坑、验证过的套路 | 知识库（knowledge_base） |
| 我排实验的手感和顺序 | 规划器（planner） |
| 我熬夜跑模型、存结果的活 | 执行器（executor） |
| 我的复盘习惯和判断标准 | 评估器（evaluator） |
| 我的取舍规则（何时深挖/何时换） | 决策引擎（decision_engine） |
| 我调权重融合的手法 | 融合优化（ensemble_optimizer） |

翻译的过程就是教程本身。翻译完，agent 能自己跑实验：23 组实验就是这么
跑出来的。

## 第 0 步 · 地基（core/）

一切比赛相关的信息（路径、列名、正类标签）只允许住在 DataConfig 里。
先写三个基础设施：

- **get_folds**：分层折，一次生成落盘、之后永远复用（冻结折）。任何实验
  对比只有同一折划分下才有意义。
- **run_cv**：统一 k 折 CV。两个必须实现的纪律：①折内门控——每折跑完
  检查累计分，明显差于参照立即中止不产出工件；②实验日志——每次实验
  追加 JSON 行，这是复盘的原始账本。
- **make_submission**：提交文件生成（带基本的值域断言）。

验证：用一份 csv 建 config，跑通一个 LightGBM 基线。

## 第 1 步 · 喂经验（knowledge_base.py）

把经验写成三层结构喂给它：

1. **普适原则**（universal_principles）：任何实验都成立的六条，详见
   [principles.md](principles.md)——这是评估器和决策引擎的阈值来源
2. **条件战术**（conditional_tactics）：带适用条件和风险的招式（如目标
   编码只对"有大量精确重复值"的特征有效），每条附验证方法和实证记录
3. **技术库**（technique_library）：具体执行协议（TE 五步法这类）

## 第 2 步 · 排计划（planner.py）

别让它乱试。阶段化、限时：

```
baseline（30min，必须完成）→ feature_engineering（2-4h）
→ model_optimization（4-8h）→ ensemble（2-4h）
```

规划器从知识库查"当前数据适用哪些战术"，生成带时间预算的实验清单。
每步到点就停——没有时间盒的探索会吃掉全部算力。

## 第 3 步 · 让它干活（executor.py）

执行交给脚本：跑模型、存 OOF、失败自动重试。三个关键机制：

- **协议化**：baseline / 交互 / TE / 多种子 / 模型矩阵，每种实验一个协议，
  输出结构一致
- **OOF 缓存**：相同(名字， 特征集， 种子)直接复用——重复实验零成本
- **折内门控**：接 core 的 FoldGateAbort，明显更差的配置在第一折就死

### 感知层：agent 的"扫榜"怎么实现

第 3 步提到的"每天扫一遍社区"，物理基础是 `tools/kaggle_mcp.py`（Kaggle 官方
MCP 服务的 CLI 封装，零依赖）：讨论区话题、新公开 notebook、榜单与自己排名、
提交状态轮询。前置只需 Kaggle access token。用法与坑见 README「感知层」一节。

## 第 4 步 · 定规矩（evaluator.py）

最重要的零件。把"什么叫有效"写成代码：

```python
delta > 0.0005          -> adopt      # 真涨，纳入最优配置
delta > 0.0003          -> candidate  # 弱正，需组合复验
|delta| < 2×噪声底      -> undecidable# 不可判定，当没看见
其余                     -> reject
```

**没有 undecidable 这一档，agent 会把运气当实力。** 噪声底用不同种子重复
整套 CV 测出来（一次性的标定工作）。

## 第 5 步 · 教它回头 + 融合（decision_engine.py + ensemble_optimizer.py）

决策引擎按规则表输出动作：

| 条件 | 动作 |
| --- | --- |
| 强信号方向存在 | 深化当前方向（调参/组合） |
| 连续 3 次实验低于噪声底 | 换方向（换模型族/集成/伪标签） |
| 有效方向 ≥ 3 个 | 转融合（单点探索的边际收益到头了） |
| CV 实验 ≥3 且无 LB 校准点 | 先提交建立校准 |
| 其他 | 继续当前计划 |

融合层：候选注册 → 去相关筛选（"多样但弱不加分"）→ 贪心加权。贪心会困在
山头，修法见 `ensemble_optimizer.py` docstring 里的"元成员注入"。

## 搭完之后

你就有一个能自己干活的队友：每晚睡前按开始，早上看账本。它会告诉你哪些
方向有效、哪些是运气、什么时候该换路——而选哪场比赛、什么时候推翻它的
方案、什么时候提交，永远是你。

## 常见坑

- **不冻结折**：实验间对比全是噪声，白干
- **全量 TE**：把验证集答案编码进特征，本地分虚高，上线现形
- **没有 undecidable 档**：运气驱动决策，方向随机漂
- **没有时间盒**：一个死方向烧光全部算力
- **全自动幻觉**：战略判断也想交给 agent——人的判断才是这个系统里
  贬值最慢的资产
