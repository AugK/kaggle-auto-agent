# 六条原则 — 详解与来源

> 这是喂给 agent 的知识库（`agent/knowledge_base.py` 的 `universal_principles`）
> 的完整版。每条原则都来自真实比赛的教训——它们不是"最佳实践清单"，是
> "不这么做会疼"的备忘录。

## 1. 代理指标 ≠ 真实目标

**原文**：代理指标(CV) ≠ 真实目标(LB)，每 3-5 个 CV 实验做一次 LB 校准。

**为什么**：本地交叉验证只是排行榜的代理。两者可以长期同向，也可以突然
背离——背离时你相信谁？没有校准点，你不知道自己的 CV 有多可信。

**做法**：CV 实验攒到 3 个还没提交过，就先提交一次建立 (CV, LB) 对应点。
之后每次校准都在更新"本地分换线上分的汇率"。

**疼的教训**：有过一场比赛，本地排序和线上排序完全对不上——根因是测试集
分布和训练集不同。如果没有早期校准点，会在错误方向上烧完全部提交额度。

## 2. 单变量对照

**原文**：单变量对照是归因前提：一次只改一个变量（含随机种子）。

**为什么**：一次改三个东西涨了 0.001，你不知道是哪个的功劳——下次想复现
就抓瞎。归因能力比单次涨分重要：能归因，好结果才可复现、坏结果才可诊断。

**做法**：实验框架的四个特征集（raw/inter/te/combo）就是为此设计的逐级
叠加；随机种子也算变量，对照实验锁定种子。

## 3. 测量分辨率决定结论粒度

**原文**：差异低于 2 倍噪声底即不可判定。

**为什么**：同一配置换 random seed 重跑，AUC 也会波动（噪声底）。低于
噪声底的"涨分"没有信息量——把它当真，等于把运气当实力。

**做法**：用不同种子重复整套 CV 测出噪声底；评估器（evaluator.py）内置
四档判决：adopt / candidate / undecidable / reject。"undecidable" 档是
这条原则的代码化——**没结论也是一种结论，且是最常见的结论**。

**疼的教训**：大量"涨了 0.0001"的实验如果按字面采信，会引导方向错误。
判 undecidable 后心态会好很多。

## 4. 最小成本先测试方向

**原文**：最小成本先测试方向，有效再放大（三折/单种子先行）。

**为什么**：全量 5 折很贵，而方向错误的实验全量跑完才知道错——用 1/3 的
成本测方向，对再放大。

**做法**：executor 内置探针模式（probe_folds）：只跑前 k 折、不算全量 OOF、
不落盘缓存（防止不完整的 OOF 污染复用池）。角点预筛用探针，确认方向用全量。

## 5. 砍特征看消融，不看重要性

**原文**：树模型单特征 gain 系统性低估低增益特征的交互贡献，砍特征决策
必须看消融 CV 而非 gain。

**为什么**：gain 排名靠后的特征，可能和别的特征有强交互——单独看没价值，
组合起来有价值。按 gain 排名砍，砍掉的常常是还没被用上的潜力股。

**做法**：任何"去掉特征 X"的决定，跑一次消融 CV 对照（有 X vs 无 X），
让分数说话。

**疼的教训**：曾按 gain 砍掉一组低增益特征，后来消融发现它们贡献了正向
增量——gain 的系统性低估是树模型的已知特性，不是这组特征不行。

## 6. 多样但弱，不加分

**原文**：（决策引擎隐含原则）多样性必须有实力托底。

**为什么**：融合时"相关性低的成员有价值"是对的，但前提是它自己不弱。
一个相关性全场最低但分数差 0.02 的模型，放进融合里的最优权重就是零——
"多样但弱"的增量是零。

**做法**：新成员过 gate：相关度检查（太像的不要）+ 分数验真（对不上的
不要）+ 三重自查（留出检验 + 千次重采样）。全过才进池。

**疼的教训**：自建深度模型与主线相关度全场最低（0.646），理论上是宝贝
多样性——但 solo 分数低 0.02，每次试探都降分，最终权重归零。"多样性没有
实力托底就是零"，这条用三次实验验证过。
